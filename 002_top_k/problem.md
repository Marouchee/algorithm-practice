# 002. 조회수 Top K 상품

상품 조회 로그 `views`(상품 id 문자열 목록)와 정수 `k`가 주어진다. 조회 수가 많은 순으로 상품 id `k`개를 반환한다. 조회 수가 같으면 id 사전순으로 앞선 것이 먼저다. 서로 다른 상품이 `k`개보다 적으면 전부 반환한다.

```python
def top_k(views: list[str], k: int) -> list[str]:
    ...
```

- `1 <= len(views) <= 10^5`, `1 <= k <= 10^5`

## 예시 (`views = ["b","a","c","a","b","a","d"]`)

| k  | 출력                  | 이유                            |
| -- | --------------------- | ------------------------------- |
| 2  | `["a","b"]`         | 조회 수 순                      |
| 3  | `["a","b","c"]`     | c와 d가 1회로 같아 사전순으로 c |
| 10 | `["a","b","c","d"]` | 상품이 4개뿐                    |

## 후속 질문

상품이 1억 개이고 k = 10이면, 전체 정렬 대신 어떻게 하는가?

## 풀이 요약

- 딕셔너리로 상품별 조회 수를 센 뒤, `key=lambda x: (-count[x], x)`로 정렬해 앞에서 k개를 자른다
- 내림차순은 숫자에 `-`를 붙여 만든다. 문자열에는 `-`를 붙일 수 없다 (TypeError)
- 튜플 key는 첫 값부터 비교하고, 같으면 다음 값으로 비교한다
- 시간: 집계 O(n) + 정렬 O(m log m) (m = 서로 다른 상품 수 ≤ n) → O(n + m log m), 최악 O(n log n)

## 실수 기록

- 마지막에 `[:k]`를 빠뜨림 → k와 상관없이 전체를 반환. 손 실행 한 번이면 잡히는 버그
- 복잡도를 `O(N + log N)`으로 답함 → 정렬은 원소 m개를 각각 비교해야 하므로 O(m log m)
