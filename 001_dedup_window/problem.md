# 001. 시간 윈도 내 중복 이벤트 제거

시간순으로 들어오는 이벤트 `(timestamp, event_id)` 목록과 윈도 길이 `W`(초)가 주어진다. 어떤 이벤트를 처리하면, 그 시각부터 `W`초가 지나기 전에 같은 `event_id`로 들어오는 이벤트는 중복으로 버린다. 처리한 이벤트를 들어온 순서대로 반환한다.

```python
def dedup(events: list[tuple[int, str]], W: int) -> list[tuple[int, str]]:
    ...
```

- 기준 시각은 같은 id를 마지막으로 **처리한** 시각이다. 버린 이벤트는 기준을 바꾸지 않는다.
- `t - 기준 시각 < W`이면 중복, `>= W`이면 다시 처리한다.
- `events`는 timestamp 오름차순(같은 값 허용). `1 <= len(events) <= 10^5`, `1 <= W <= 10^9`.

## 예시 (`W = 10`)

```
입력: [(1,"a"), (3,"b"), (5,"a"), (11,"a"), (12,"b"), (13,"b"), (20,"a"), (21,"a")]
출력: [(1,"a"), (3,"b"), (11,"a"), (13,"b"), (21,"a")]
```

| 이벤트 | 판정 | 이유 |
|---|---|---|
| (1,a) | 처리 | 첫 a |
| (3,b) | 처리 | 첫 b |
| (5,a) | 버림 | 5 − 1 = 4 < 10 |
| (11,a) | 처리 | 11 − 1 = 10 (경계값은 처리) |
| (12,b) | 버림 | 12 − 3 = 9 |
| (13,b) | 처리 | 13 − 3 = 10. 버린 (12,b)는 기준이 아님 |
| (20,a) | 버림 | 20 − 11 = 9 |
| (21,a) | 처리 | 21 − 11 = 10 |

## 후속 질문

새 id가 계속 들어오면(UUID 등) 딕셔너리가 무한히 커진다. 메모리를 윈도 크기로 묶으려면?

## 풀이 요약

- **dict 버전:** id별 마지막 처리 시각을 저장. 시간 O(n), 공간 O(서로 다른 id 수)
- **deque 버전:** 처리한 이벤트만 `(시각, id)`로 큐에 넣고, 매 이벤트마다 **먼저** 만료된 항목을 앞에서 꺼내 딕셔너리에서도 지운 뒤 판정한다. 각 항목은 한 번 들어가고 한 번 나오므로 시간 O(n), 공간 O(윈도 안의 id 수)
- **불변식:** 처리한 이벤트만 넣으므로 큐 안에서 id는 유일하다 → `del`이 안전하다

## 실수 기록

- `while q and q[0]:` → 비어 있지 않은 튜플은 항상 참이라 매번 큐를 전부 비움. 에러 없이 모든 이벤트가 통과하는 버그
- 판정을 먼저 하고 만료를 나중에 하면, 방금 갱신한 값을 옛 항목이 지울 수 있다 → 만료 처리가 먼저
